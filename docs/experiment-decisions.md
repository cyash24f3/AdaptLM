# Decisions before final generative test exposure

The selected checkpoint is the official 1.54B Qwen2.5-Instruct candidate with a pinned Apache-2.0 license. The small, local, nonquantized model fits this Mac's storage and offers genuine instruction following. Initial validation exposed unreliable raw output; there is no claim this was the best model from a broad search. The central experiment keeps the same model revision for base/adapted comparison.

PyTorch 2.8 trials showed unrelated/repetitive SDPA outputs, and eager-attention main training exceeded memory. The eager retry was interrupted during the runtime investigation. The current controlled experiment uses PyTorch 2.14.0, explicit MPS/BF16, SDPA, bounded padding, and cache handling. The upstream MPS issue is relevant context, not proof that every failure was caused by one bug. Historical outputs remain in reports and are not mixed into final scores. Dependency locks at main-run start are retained in configs/locks/main-214-start.lock.

The main adapter's training prompt is v1. During validation and code inspection, the literal span examples in v1 were found to have inconsistent placeholder lengths. Production prompt v2 corrects those two examples without changing the label schema or category rules. Both base and adapted weights receive **the identical v2 prompt and decoding settings** in the controlled final comparison. The training prompt version remains v1 in the bundle; it is never relabeled as v2. Only registered known prompt hashes can load. The model metadata exposes both versions. This is a matched inference comparison with a documented small training/production prompt difference; future training should use v2.

The initial three few-shot demonstrations lacked populated entities and out-of-scope behavior. The revised coverage-v2 rule selects four shortest train examples within fixed roles: filled entities/operational fields, missing details/Unicode, ambiguity, and out-of-scope. Exact IDs and actual tokenizer counts are saved in runtime/prediction records. This update occurred before final generative test evaluation. No test output informed it.

Main LoRA hyperparameters: one epoch, rank 8/alpha 16, q_proj/v_proj, 0.05 dropout, learning rate 2e-4, linear schedule with 5% warm-up, microbatch one/accumulation eight, seed 42, no packing, no quantization. Selection uses the lowest completion cross entropy over 20 fixed validation scenario examples at saved checkpoints 55 and 110. The rest of validation remains available for generated-output evaluation. A training-loss improvement alone is not complete-record quality.

The final test should use the frozen authored split, greedy decoding, unchanged output budget 384, exact original messages, zero-shot/few-shot/adapted on identical IDs, and all-attempted metrics. Raw span validity is a hard application requirement; semantic summary support is independently unreviewed. Category-only classifier results and full generative records are reported on their genuine output fields. No universal accuracy target or guaranteed fine-tuning improvement is asserted. Final operating targets will be tied to observed validation rates, with exact definitions, before the test.
